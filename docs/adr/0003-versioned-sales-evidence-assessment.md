# Use versioned evidence rules for the returning-customer assessment

Sales sessions created with the OpenRouter pipeline use Jev to recognize independent acts in the current player utterance. Backend rules own objectives, disclosed facts, violation events, rubric components and customer trust. Qwen writes Lan's speech from a backend plan; its wording cannot create a score or ending. This replaces the final LLM scoring call for new v2 sessions while retaining it for legacy sessions.

Each session freezes its pipeline, rubric, scenario, question set, thresholds and writer prompt versions. Each rubric component is earned once in its objective context. A committed monetary-policy violation remains in the penalty ledger after retraction, while retraction clears the outstanding promise. Critical uncertainty holds the assessment for clarification or review instead of producing a failed score. Only a completed backend assessment can finalize the simulation-run result.

HTTP still carries one complete, idempotent audio turn. Checkpoints reuse successful transcription, classification and writing stages for the same turn ID and audio hash. Supertonic consumes committed customer text. Local microphone capture and an A-button playback interruption do not make this a continuous two-way audio protocol. A future change to that protocol requires a separate decision.

The tradeoff is explicit network dependency and the need to calibrate a full label set. Legacy remains the rollout default. Shadow observations do not control the session or regrade historical results. Operator secrets are injected into NCKH-AI; the backend does not discover credentials in adjacent workspaces.
